># I. Scoping Document Detection and “Material Change” Heuristics
>
>1. Identify “scoping docs” using allowlisted path patterns:
>
>   * `docs/features/**/spec.md`
>   * `docs/features/**/plan.md`
>   * `docs/features/**/bug-remediation-plan.md`
>   * `docs/features/**/user-story.md`
>   * optionally `docs/features/**/README.md`
>
>2. From the computed PR range diff, determine which scoping docs changed.
>
>3. Classify scoping-doc changes into:
>
>   * `Scoping docs changed (material)`
>   * `Scoping docs changed (non-material)`
>
>4. Determine “material” deterministically using these heuristics:
>
>   * Magnitude threshold:
>
>     * Use numstat (insertions + deletions) for each file.
>     * If total changed lines >= 15, mark material.
>
>   * Section-level targeting:
>
>     * If the diff touches headings matching:
>
>       * “Context”
>       * “Root Cause”
>       * “Proposed Fix”
>       * “Acceptance Criteria”
>       * “Test Strategy”
>       * “Risks”
>         mark material even if change magnitude is small.
>
>   * Mechanical-only filters:
>
>     * If diff appears dominated by whitespace-only or link-only changes, mark non-material.
>     * Implement via deterministic pattern checks (e.g., changed lines are mostly URLs or markdown link syntax; or changes are only whitespace).
>
>   * New file detection:
>
>     * Any newly added scoping doc is material.
>
>5. For each scoping doc in the “material” list:
>
>   * Include excerpt blocks in the summary output for relevant headings (Acceptance Criteria, Root Cause, Proposed Fix, Test Strategy).
>   * Apply truncation budgets and annotate truncation.
>
>6. For multiple active feature folders:
>
>   * Compute a “materiality score” per feature folder:
>
>     * based on number of material scoping docs changed and/or total changed lines.
>   * Choose the top 1–2 feature folders as primary drivers for the eventual PR “Why” and mark them as such in the summary.
